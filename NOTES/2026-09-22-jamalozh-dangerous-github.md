## Суть

Публичность репозитория не равна безопасности.

В рилсе речь о проектах, которые выглядят «полезными»: скачивалки видео почти с любой платформы и обёртки, которые подменяют платные сервисы (YouTube Premium, Microsoft Office, Adobe, стриминги) «использованными фантиками». Автор прямо просит такие штуки **не использовать**: это бьёт и по экосистеме, и по тебе (трояны, стилеры, поддельные релизы).

Копаться на GitHub и находить сильные репозитории — нормально. Ставить первый попавшийся «crack / premium / free office» — нет.

## Что было в комментариях (не как рекомендация)

Люди всплывали yt-dlp, Smartube, «Флинт», пиратские обходы подписок. Это как раз зона, где рилс предупреждает: «вы знаете о чём я говорю — не надо».

## Практический вывод для заметок

Собирать можно:

- известные OSS-инструменты с историей, лицензией, живыми мейнтейнерами;
- awesome-списки;
- свои форки и черновики.

Не собирать:

- cracks, keygen, «premium forever», «free Netflix/YouTube Premium»;
- репо с одним релизом-ZIP и нулевой историей;
- MCP/скиллы для агентов без аудита.

## Чеклист перед `git clone`

1. Организация / автор существует давно, не 14-дневный аккаунт.
2. Лицензия есть.
3. Коммиты живые, не один «Initial commit + Release.zip».
4. Stars/forks не купленные (смотреть issues и PR).
5. Релиз качается с GitHub Releases того же репо, не с стороннего «официального сайта».
6. Для агентов: не ставить MCP с каталогов вслепую.
